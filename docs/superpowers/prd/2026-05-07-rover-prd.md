# Rover — Product Requirements Document

> An MCP server for fetching and prepping web content for LLM agents

## 1. Overview

**Rover** is a Rust-based MCP (Model Context Protocol) server that turns web pages into clean, token-efficient Markdown for LLM agents. It fetches URLs, extracts the meaningful content, converts to Markdown, optionally compacts/summarizes, and caches everything sensibly.

The hard part — extracting meaningful content from cluttered HTML — is delegated to the [`readabilityrs`](https://crates.io/crates/readabilityrs) crate, which handles HTML cleanup and Markdown conversion including normalization of vendor-specific patterns (Prism/Shiki/rehype/WordPress/GitHub code blocks, lazy-loaded images, MathJax/KaTeX, footnote dialects, permalink anchors). Rover layers on the agentic prep work: caching, steered summarization, metadata extraction, token budgeting, batch coordination, and the operational concerns (rate limiting, SSRF protection, robots.txt, charset detection).

**Target deployment:** Single-user local MCP server. Distributed as an open-source Rust binary.

**Primary clients:** Claude Code (and other MCP-speaking LLM agent harnesses).

## 2. Scope

### V1 — In Scope

- Single-URL fetch with extraction to Markdown
- Batch URL fetch with task coordination
- HTTP cache with respectful TTL handling
- HAR-format debug logging
- Steered summarization (extractive + abstractive)
- Multi-provider BYOK summarization (OpenAI, Anthropic, Gemini, OpenAI-compatible endpoints like LM Studio/Ollama/vLLM)
- Schema.org / Open Graph / Twitter Card metadata extraction
- Token counting for major model families
- SSRF protection with configurable levels
- Per-domain rate limiting with `429`/`Retry-After` honoring
- Robots.txt respect (configurable)
- Charset detection
- URL canonicalization (3xx redirects, `rel="canonical"`, `Link` header)
- Relative-to-absolute link rewriting in output
- Long-running task model with NDJSON-streaming CLI for Monitor-tool integration
- Single binary serving both CLI and MCP server roles

### V1 — Behind Cargo Feature Flags

- `local-inference` — local LLM summarization via `mistral.rs` (default model: Qwen 3.5 0.8B)
- `vlm` — image captioning via SmolVLM
- `headless` — JavaScript-rendered SPA support via `chromiumoxide`

### V2 — Explicitly Deferred

- Embeddings sidecar
- Section-aware chunking for RAG
- Diff mode (re-fetch and return changes)
- Authentication/cookie support for paywalled content
- Multi-format output (JSON chunks, plain text)
- Watch mode / scheduled re-polling

### Out of Scope (Will Not Build)

- PDF input — agents should use a separate PDF→HTML tool, then point Rover at a `file://` URL
- Office formats (docx, pptx, xlsx) — same reasoning
- Audio transcription
- RSS/Atom feed parsing — outside the "render arbitrary HTML" core mission
- Sitemap-aware crawling — Rover is not a spider
- Archive.org fallback — out of scope for the prep layer
- Section-aware chunking
- Topic extraction as a distinct feature (metadata extraction covers the structured cases)

## 3. Architecture

### 3.1 Single Binary, Subcommand Dispatch

One Rust binary, `rover`, dispatches on its first argument:

```
rover mcp                            Start the MCP server (long-running)
rover fetch <url> [opts]             One-shot fetch, prints markdown to stdout
rover batch <uuid> [--monitor]       Status snapshot (default) or NDJSON stream (--monitor)
rover task <uuid> [--monitor]        Generic task status, same shape as batch
rover cache list                     List cached URLs
rover cache get <url>                Retrieve cached content
rover cache purge <pattern>          Purge by URL or glob
rover cache stats                    Cache size, hit rate, etc.
rover doctor                         Verify models, network, dependencies, paths
rover config show                    Print effective config
rover config set <key> <value>       Mutate config
```

Use `clap` with derive macros for subcommand definitions. All subcommands share the same internal modules (`storage`, `fetcher`, `extractor`, `summarizer`, `tasks`, `metadata`, `tokenizer`).

### 3.2 Storage

A single SQLite database serves as the source of truth for cache, task state, and event log. Default location: `$XDG_DATA_HOME/rover/rover.db` (or `~/.local/share/rover/rover.db`).

**Critical:** enable WAL mode at startup (`PRAGMA journal_mode = WAL`). The MCP server (writer) and CLI subcommands (readers) need concurrent access; without WAL you'll get `database is locked` errors immediately.

### 3.3 Inter-process Coordination

The MCP server is the only writer. CLI subcommands like `rover batch <uuid>` are pure readers — they query SQLite and exit (or poll-loop on `--monitor`). No sockets, no IPC, no shared memory.

**Heartbeat row:** the MCP server updates a `system.last_heartbeat` row every ~5 seconds. CLI subcommands check this row to detect "MCP server not running but task marked running" cases and warn the user.

**Task resumption:** on `rover mcp` startup, scan for tasks with `status='running'`. Per task kind:
- `batch_fetch`, `retry`: resume from persisted progress
- `summarization`: mark `failed` with `error='mcp_server_restarted'`, let the agent re-request

## 4. MCP Tool Surface

The MCP server exposes the following tools. All tools should support the standard MCP request/response pattern; long-running variants return a `task_id` and use the Monitor pattern (§9).

### 4.1 `fetch`

Fetch a single URL, extract to Markdown, optionally summarize.

**Arguments:**
- `url: string` (required)
- `force_refresh: bool = false` — bypass cache
- `headless: bool | "auto" = "auto"` — force/disable headless browser; `"auto"` triggers SPA detection
- `tables: TablesOpts` — see §6.3
- `images: ImagesOpts` — see §6.4
- `metadata: MetadataOpts` — see §6.5
- `summarize: SummarizeOpts | null` — when present, apply summarization
- `max_tokens: int | null` — hard budget; auto-summarize if exceeded
- `count_only: bool = false` — return only token estimates, not content
- `tokenizer: string = "cl100k"` — `cl100k`, `o200k`, `claude`, `llama3`, `qwen3`

**Returns:**
- On success: `{content: string, metadata: object, cache_status: "hit"|"miss"|"stale_served"}`
- On `count_only`: `{estimates: {raw_html, extracted_md, summary_short, summary_medium}}`
- On stale-served: includes `revalidation_task_id` for optional monitoring
- On failure that schedules retry: `{status: "deferred", task_id, monitor_command, poll_command, hint}`

### 4.2 `batch_fetch`

Fetch multiple URLs concurrently with per-domain rate limiting.

**Arguments:**
- `urls: string[]` (required, max 100)
- All single-fetch options apply per-URL
- `concurrency: int = 8` — global cap
- `per_domain_concurrency: int = 2` — per-host cap

**Returns immediately:**
```json
{
  "task_id": "batch_abc123",
  "status": "started",
  "kind": "batch",
  "total_urls": 50,
  "monitor_command": "rover batch batch_abc123 --monitor",
  "poll_command": "rover batch batch_abc123",
  "hint": "Use the Monitor tool with monitor_command for live updates, or call poll_command to check status."
}
```

Final results retrievable via `rover task <id>` once complete, or pushed via NDJSON during `--monitor`.

### 4.3 `summarize`

Apply summarization to existing cached content or a fresh URL.

**Arguments:**
- `url: string` (required)
- `target_tokens: int | null` — soft target
- `mode: "extractive" | "abstractive" | "headlines" = "abstractive"`
- `focus: string | null` — free-form steering prompt
- `preserve: ("code"|"tables"|"quotes"|"lists")[] = []` — never touch these
- `style: "bullet" | "prose" | "executive" = "prose"`
- `backend: string | null` — named backend from config; `null` uses default

**Returns:** summarized Markdown.

### 4.4 `get_metadata`

Return only the metadata frontmatter for a URL, no body. Useful for triage.

**Arguments:**
- `url: string` (required)
- `metadata: MetadataOpts`

**Returns:** parsed metadata object.

### 4.5 `count_tokens`

Estimate token counts for various transformations of a URL without returning content.

**Arguments:**
- `url: string` (required)
- `tokenizer: string = "cl100k"`

**Returns:**
```json
{
  "url": "...",
  "estimates": {
    "raw_html": 14823,
    "extracted_md": 2891,
    "summary_short": 312,
    "summary_medium": 891
  }
}
```

## 5. HTTP Fetcher

### 5.1 Charset Detection

**Mandatory pipeline** (use `encoding_rs` + `chardetng`):

1. Check BOM via `Encoding::for_bom(bytes)`. If present, use that encoding.
2. Check HTTP `Content-Type` charset parameter. If valid (`Encoding::for_label`), use it.
3. ASCII-decode the first 1024 bytes and regex-scan for `<meta charset="...">` or `<meta http-equiv="Content-Type" content="...; charset=...">`. If found, use that.
4. Run `chardetng::EncodingDetector` over the bytes; use `.guess(None, true)`.
5. Fallback: UTF-8 with replacement chars.

Always re-encode the final output to UTF-8 before storage or return. Log when HTTP-declared charset differs from detected — useful diagnostic.

**Do not** rely on `reqwest`'s `.text()` auto-detection; fetch as `.bytes()` and run the pipeline yourself.

### 5.2 Redirects

- Follow `301`, `302`, `307`, `308` with a max chain of 10
- For `301`/`308` (permanent), the final URL becomes the canonical store key
- For `302`/`307` (temporary), cache against the requested URL, not the destination
- Honor `rel="canonical"` from HTML `<link>` tag and from `Link:` HTTP header
- Stale `rel=canonical` happens (sites pointing canonical at a 404); validate before trusting

### 5.3 Conditional Requests

- Store `ETag` and `Last-Modified` from every response
- On revalidation, send `If-None-Match` and `If-Modified-Since`
- `304 Not Modified` → bump `fetched_at` on existing cache row, skip body processing

### 5.4 Rate Limiting

Per-domain token bucket. Configuration: `requests_per_minute_per_domain` (default 60).

- Honor `429 Too Many Requests` with `Retry-After` (handle both seconds-as-int and HTTP-date formats)
- Honor `503` with `Retry-After`
- Other 5xx: exponential backoff with jitter, max 3 retries within a single sync call (longer retries become deferred tasks)
- Honor `Crawl-Delay` from robots.txt as a floor on the rate limiter

### 5.5 SSRF Protection

Configurable level, default `strict`:

| Level | Allows |
| --- | --- |
| `strict` | Public IPs only, http/https only |
| `loopback` | Strict + 127.0.0.0/8, ::1 |
| `project` | Loopback + `file://` URLs within configured project root |
| `lan` | Project + RFC1918 (10/8, 172.16/12, 192.168/16) and IPv6 ULAs (fc00::/7) |
| `none` | Trust the user; document the risk |

**Implementation requirements regardless of level:**
- DNS rebinding protection: resolve hostname once, validate the IP, then fetch using the resolved IP with the original `Host` header set
- Block link-local (169.254.0.0/16, fe80::/10), multicast, broadcast, `0.0.0.0`, `255.255.255.255`
- Only allow `http://` and `https://` schemes (plus `file://` at `project` level and above)
- For `file://` at `project` level: canonicalize the path, then verify it's a descendant of the configured project root *after* symlink resolution

### 5.6 Robots.txt

Default behavior: respect. Configurable to ignore globally or per-domain.

- Use the `robotxt` or `texting_robots` crate; do not write your own parser (RFC 9309 has surprising edge cases)
- Cache parsed robots.txt per host in SQLite
- TTL: honor robots.txt's own `Cache-Control` if present, else 24 hours
- Honor `Crawl-Delay` and `User-Agent`-specific rules
- Send a stable, identifiable User-Agent (e.g., `Rover/0.1 (+https://github.com/.../rover)`)

### 5.7 Headless Browser (`headless` feature flag)

Use `chromiumoxide` for SPA support.

**SPA detection heuristics** — apply when `headless: "auto"` and the initial fetch produces poor extraction:
- Extracted text length < 300 characters after readability pass
- Presence of known SPA markers: `<div id="root">`, `<div id="app">`, `<div id="__next">`, `__NEXT_DATA__`, `__NUXT__`, `window.__INITIAL_STATE__`
- High `<script>`-to-content ratio
- Only-anchor-link patterns (`<a href="#/route">`)
- `<noscript>` containing only "JavaScript required"-style messages

If two or more heuristics fire, retry with headless.

**Asset filtering via CDP:** **fulfill blocked requests with empty 200 responses, not aborts.** Many SPAs error hard on failed CSS/font requests but handle empty stylesheets gracefully.

Defaults:
- `block_media: true` (video/audio always)
- `block_images: true` (override per-call when image content matters)
- `block_fonts: true`
- `block_css: false` (default; some sites use CSS for content reveal)
- `block_third_party: true` (use a minimal EasyList-derived domain list)
- `block_service_workers: true`

**Wait conditions:** default `domcontentloaded`. Configurable to `networkidle2` for stubborn SPAs. Configurable timeout (default 15s). Long renders should defer to a task.

## 6. Content Extraction

### 6.1 Pipeline

```
bytes → charset_detect → utf8 → readabilityrs → markdown_postprocess → output
```

`readabilityrs` handles the HTML-to-Markdown conversion including most normalization concerns. Configure its `MarkdownOptions` for LLM-friendly output:
- ATX-style headings (`#`)
- Backtick code fences
- Dash bullets
- Inline links (not reference style)

### 6.2 Output Envelope

YAML frontmatter wrapping the Markdown body:

```yaml
---
url: https://example.com/article?utm_source=twitter
canonical_url: https://example.com/article
title: How to do the thing
fetched_at: 2026-05-07T12:34:56Z
content_hash: sha256:abc123...
estimated_tokens: 1842
language: en
extraction_quality: 0.87
schema_types: [Article, BreadcrumbList]
author: Jane Doe
published: 2026-04-15T09:00:00Z
modified: 2026-04-20T14:00:00Z
description: Article description here
image: https://example.com/og-image.jpg
tables_transformed:
  - id: t1
    original_rows: 412
    applied_mode: sample
  - id: t2
    original_rows: 89
    applied_mode: csv_file
    csv_path: ./tables/t2.csv
---

# Article body in Markdown follows...
```

### 6.3 Tables

```rust
struct TablesOpts {
    mode: TablesMode,                   // default: Embed
    row_threshold: usize,               // default: 50
    col_threshold: usize,               // default: 12
    sample_strategy: SampleStrategy,    // default: HeadTail
}

enum TablesMode { Embed, Sample, Summarize, CsvFile, Drop }
enum SampleStrategy { HeadTail, Stratified, RandomSeed(u64) }
```

When a table exceeds `row_threshold` or `col_threshold`, apply the configured `mode`:
- `Embed`: include as-is (default — let the agent deal with it)
- `Sample`: keep first/last N rows or a sample, mark with `[... truncated ...]`
- `Summarize`: replace with a one-paragraph natural-language summary (uses summarization backend)
- `CsvFile`: write to a sidecar CSV in the configured output dir, replace with a Markdown link
- `Drop`: replace with `[table omitted]`

For every transformed table, append an entry to `tables_transformed` in the frontmatter so the agent knows what happened.

### 6.4 Images

```rust
struct ImagesOpts {
    mode: ImagesMode,                   // default: AltTextOnly
    vlm_model: Option<String>,          // when mode = CaptionVlm; "vlm" feature required
    caption_max_tokens: usize,          // default: 50
    download_dir: Option<PathBuf>,      // when mode = Download
}

enum ImagesMode { Keep, AltTextOnly, CaptionVlm, Download, Drop }
```

- `Keep`: preserve `![alt](url)` as-is
- `AltTextOnly` (default): strip `url`, keep alt text inline as plain text
- `CaptionVlm`: replace alt text with VLM-generated caption (requires `vlm` feature; see §7.3)
- `Download`: fetch images to `download_dir`, rewrite paths to local
- `Drop`: remove all image references

### 6.5 Link Rewriting

Convert all relative URLs to absolute. Resolution order:
1. If `<base href="...">` present in `<head>`, use that as the base
2. Else use the final response URL after redirects

Use `url::Url::join` from the `url` crate. Apply to:
- `<a href>`, `<img src>`, `<link href>`, `<script src>`
- `srcset` attributes (parse the grammar — comma-separated, each entry is URL + descriptor)
- CSS `url(...)` references if CSS is being preserved

### 6.6 Metadata Extraction

```rust
struct MetadataOpts {
    preset: MetadataPreset,             // default: Default
    fields: Option<Vec<String>>,        // overrides preset if set
}

enum MetadataPreset { Default, All, Minimal }
```

**Default preset fields** (extracted from JSON-LD, OG, Twitter Cards, microdata, HTML head):
- `title`, `description`, `author`, `published`, `modified`, `image`, `og:type`, `canonical`

**Minimal preset:** just `title` and `canonical`.

**All preset:** dump everything parsed.

Always surface `schema_types: [...]` (the JSON-LD `@type` values found) so the agent can discover what's available even with the default preset.

JSON-LD lives in `<script type="application/ld+json">` blocks. Parse with `serde_json::Value` and walk for known types. Open Graph is `<meta property="og:*">`. Twitter Cards are `<meta name="twitter:*">`. Microdata is `itemtype`/`itemprop` attributes (consider the `microdata` crate).

## 7. Summarization

### 7.1 Backend Trait

```rust
#[async_trait]
trait SummarizerBackend: Send + Sync {
    async fn compact(&self, content: &str, opts: &CompactOpts) -> Result<String, BackendError>;
    fn name(&self) -> &str;
}
```

Implementations:
- `LocalMistralRs` — embedded inference (feature `local-inference`)
- `Cloud(genai::Client)` — wraps the [`genai`](https://github.com/jeremychone/rust-genai) crate (covers OpenAI, Anthropic, Gemini, xAI, Groq, DeepSeek, Together, Fireworks, plus custom URL via `ServiceTargetResolver` for OpenAI-compatible endpoints)
- `Extractive` — own implementation, no model required

Users define backends in config:

```toml
[backends.fast]
kind = "cloud"
provider = "openai"
model = "gpt-4o-mini"

[backends.local]
kind = "local"
model = "Qwen/Qwen3.5-0.8B"

[backends.lm_studio]
kind = "cloud"
provider = "openai_compat"
base_url = "http://localhost:1234/v1"
model = "qwen3.5-0.8b"

[backends.smart]
kind = "cloud"
provider = "anthropic"
model = "claude-sonnet-4-7"

default_backend = "extractive"
```

API keys via env vars (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, etc.) per `genai` conventions.

### 7.2 Extractive Summarization

Roll your own minimal TextRank — do not depend on stale crates. Implementation outline:

1. Sentence segmentation via `unicode-segmentation` (sentence boundaries per Unicode Annex #29) or `icu_segmenter` (more accurate, larger dep — your call)
2. TF-IDF vectors per sentence with `HashMap<&str, f32>`
3. Sentence similarity graph via cosine similarity; threshold weak edges
4. PageRank for ~20 iterations or until convergence (damping 0.85, tolerance 1e-4)
5. Select top-k sentences ordered by original position

Should be ~250 lines of Rust. Deterministic, fast, no external deps beyond standard crates.

### 7.3 Local Inference (`local-inference` feature)

Use [`mistral.rs`](https://github.com/EricLBuehler/mistral.rs) as the engine. Default model: **Qwen 3.5 0.8B** (262K context window, multilingual, small footprint).

Don't hardcode the model — accept `--model <hf_repo_id>` and let `mistral.rs` resolve. Document Qwen 3.5 0.8B as the default but make swapping trivial.

When the Qwen 3.6 series releases small variants, swap; until then, 3.5 is the right choice (3.6 currently exists only at 27B and 35B-A3B sizes as of May 2026).

### 7.4 Image Captioning (`vlm` feature)

Use **SmolVLM** (256M, 500M, or 2.2B variants) for image-to-text via `mistral.rs`. The 256M variant uses < 1GB GPU memory and is appropriate for batch image captioning where you don't want each image to cost thousands of inference tokens.

### 7.5 Compaction Steering

```rust
struct CompactOpts {
    target_tokens: Option<usize>,
    mode: CompactMode,                  // Extractive | Abstractive | Headlines
    focus: Option<String>,              // free-form prompt
    preserve: Vec<PreserveSection>,     // Code | Tables | Quotes | Lists
    style: Style,                       // Bullet | Prose | Executive
    backend: Option<String>,            // named backend; None = default
}
```

For `Abstractive`, build the system prompt from the opts. Sample template:

```
Summarize the following content. Target length: ~{target_tokens} tokens.
Style: {style}.
{if focus}: Focus on: {focus}.
{if preserve}: Preserve these elements verbatim: {preserve_list}.
Do not add information not present in the source.
```

## 8. Caching

### 8.1 Schema

```sql
CREATE TABLE pages (
    url_hash      TEXT PRIMARY KEY,        -- sha256(canonical_url)
    url           TEXT NOT NULL,
    canonical_url TEXT,
    title         TEXT,
    fetched_at    INTEGER NOT NULL,        -- unix epoch
    expires_at    INTEGER,                 -- computed from headers + config
    etag          TEXT,
    last_modified TEXT,
    content_hash  TEXT NOT NULL,           -- sha256 of extracted_md
    extracted_md  TEXT NOT NULL,
    metadata_json TEXT,                    -- JSON blob
    raw_html_zstd BLOB                     -- optional, behind config flag
);
CREATE INDEX pages_expires ON pages(expires_at);
CREATE INDEX pages_content_hash ON pages(content_hash);

CREATE TABLE summary_cache (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    content_hash  TEXT NOT NULL,
    params_hash   TEXT NOT NULL,           -- sha256 of (model, mode, target, focus, preserve, style)
    summary_md    TEXT NOT NULL,
    created_at    INTEGER NOT NULL,
    UNIQUE(content_hash, params_hash)
);

CREATE TABLE robots_cache (
    host         TEXT PRIMARY KEY,
    body         TEXT,
    fetched_at   INTEGER,
    expires_at   INTEGER
);

CREATE TABLE tasks (
    id           TEXT PRIMARY KEY,
    kind         TEXT NOT NULL,            -- batch | retry | revalidate | summarize
    status       TEXT NOT NULL,            -- pending | running | completed | failed | cancelled
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    params_json  TEXT,
    result_json  TEXT,
    cancellation_requested INTEGER DEFAULT 0
);

CREATE TABLE task_events (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id      TEXT NOT NULL,
    ts           INTEGER NOT NULL,
    kind         TEXT NOT NULL,
    payload_json TEXT
);
CREATE INDEX task_events_by_task ON task_events(task_id, id);

CREATE TABLE system (
    key          TEXT PRIMARY KEY,
    value        TEXT
);
-- system contains: 'last_heartbeat', 'schema_version', etc.
```

### 8.2 TTL Logic

Order of precedence:

1. If `Cache-Control: no-store` and `cache.override_no_store == false` and host not in `cache.override_no_store_domains` → don't cache at all
2. If `min_ttl` is configured, ensure final TTL ≥ `min_ttl` (this is the only way `no-store` can be overridden)
3. If `max-age` or `s-maxage` present in `Cache-Control`, use it
4. Else if `Expires` header present, use it
5. Else use `cache.default_ttl`
6. Cap final TTL at `cache.max_ttl`

Configuration:

```toml
[cache]
default_ttl = "1h"
min_ttl = "5m"
max_ttl = "7d"
override_no_store = false
override_no_store_domains = []
store_raw_html = false              # zstd-compressed raw, for debugging
```

### 8.3 Stale-While-Revalidate

When a request hits expired cache:
1. Return the stale content immediately
2. Spawn an async revalidation task; include `revalidation_task_id` in the response metadata
3. Agent can monitor or ignore at its discretion

### 8.4 Summary Cache

`summary_cache` is keyed on `(content_hash, params_hash)`. Same content with different summarization params → independent cache entries. Same content under different URLs (mirrors, syndication) → reuse.

`params_hash` should be deterministic over: model name, mode, target_tokens, focus prompt, preserve list, style. Sort keys before hashing.

### 8.5 Cache Operations

CLI surface (§3.1):
- `rover cache list` — paginated URL list with sizes and ages
- `rover cache get <url>` — print cached Markdown
- `rover cache purge <pattern>` — accept literal URL or glob (e.g., `https://docs.example.com/*`)
- `rover cache stats` — total size, entry count, hit rate (last 24h), expired count

MCP-side: `force_refresh: true` arg on `fetch` and `batch_fetch` bypasses cache for that call.

## 9. Long-Running Tasks

### 9.1 The Pattern

When a tool starts work that may take more than ~5 seconds (batch fetches, async retries, slow headless renders, SWR revalidation), it returns immediately with a `task_id` and instructions for monitoring:

```json
{
  "task_id": "abc123",
  "status": "started",
  "kind": "batch",
  "monitor_command": "rover batch abc123 --monitor",
  "poll_command": "rover batch abc123",
  "hint": "Use the Monitor tool with monitor_command for live updates, or call poll_command periodically to check status."
}
```

The agent decides which path to take based on its capabilities. Claude Code agents will use Monitor; agents without Monitor will poll.

### 9.2 CLI: `rover batch <uuid>` and `rover task <uuid>`

**Without `--monitor`:** print a snapshot and exit.

Default human-readable output:
```
Batch abc123 — running
Started 12s ago
Progress: 35/50 (70%)  ✓ 33  ✗ 2  ⋯ 15 in flight
ETA ~5s
Last event: item_done https://example.com/foo (1.2s ago)
```

With `--format=ndjson`: emit a single JSON line with current state, then exit.

**With `--monitor`:** stream NDJSON until task reaches a terminal state (completed/failed/cancelled).

```jsonl
{"ts":"2026-05-07T12:00:00.000Z","kind":"batch_start","total":50}
{"ts":"2026-05-07T12:00:01.234Z","kind":"item_done","url":"https://...","tokens":1842,"cached":false}
{"ts":"2026-05-07T12:00:01.890Z","kind":"item_failed","url":"https://...","error":"timeout","will_retry":true,"retry_in_s":4}
{"ts":"2026-05-07T12:00:12.345Z","kind":"final","succeeded":48,"failed":2,"duration_s":12.3}
```

**Implementation:** the `--monitor` loop reads `task_events` rows for this task with `id > last_seen_id`, prints them as NDJSON, sleeps 200ms, repeats. Exit when the `tasks` row's `status` is terminal. Trap `SIGINT` for clean exit.

### 9.3 Cancellation

`rover task <uuid> --cancel` sets `tasks.cancellation_requested = 1`. Workers in the MCP server check this flag at safe points (between URLs in a batch, between retry attempts, at chunk boundaries in summarization). Cooperative — do not pursue hard kill semantics.

### 9.4 Liveness

CLI subcommands check the `system.last_heartbeat` row before reporting status. If `now() - last_heartbeat > 30s` and the task is `running`, warn:

> ⚠ Task is marked `running` but no `rover mcp` process appears to be alive.
> Restart the MCP server with `rover mcp` to resume work.

## 10. Token Counting

Two crates cover the field:

- [`tiktoken-rs`](https://crates.io/crates/tiktoken-rs) for OpenAI-family tokenizers (`cl100k_base`, `o200k_base`)
- [`tokenizers`](https://crates.io/crates/tokenizers) (Hugging Face's official Rust crate) for everything else (Claude, Llama, Qwen, Gemma)

Supported `tokenizer` arg values: `cl100k`, `o200k`, `claude`, `llama3`, `qwen3`. Document mapping to actual tokenizer IDs. Cache loaded tokenizers in memory.

For `count_only: true` requests, return:
```json
{
  "url": "...",
  "estimates": {
    "raw_html": 14823,
    "extracted_md": 2891,
    "summary_short": 312,
    "summary_medium": 891
  }
}
```

`raw_html` is an estimate against the cleaned-but-not-extracted HTML. `summary_short` and `summary_medium` are *predictions*, not actual summarizations — heuristic based on content length and historical compression ratios. Document this clearly.

## 11. Debug & Diagnostics

### 11.1 HAR Mode

Configurable: `debug.har_path = "./debug.har"`. When set, every fetch records a [HAR (HTTP Archive)](http://www.softwareishard.com/blog/har-12-spec/) entry: request line, request headers, response status, response headers, response body (up to a configurable size cap), timings.

Use the [`har`](https://crates.io/crates/har) crate — do not hand-roll the schema. The output is viewable directly in Chrome DevTools' Network panel (Import HAR file).

### 11.2 `rover doctor`

Verifies the Rover environment:
- SQLite DB exists and is writable, schema version matches
- WAL mode enabled
- Network reachability (try fetching `https://example.com`)
- For `local-inference` feature: model files cached, mistral.rs loads
- For `vlm` feature: VLM model files
- For `headless` feature: chromiumoxide can find/launch a browser
- Configured backends authenticate (try a trivial completion against each cloud backend)
- Output dir writable

Exit code 0 if all checks pass, 1 if any fail. NDJSON mode for scripting.

## 12. Configuration

```toml

[fetch]

max_redirects = 10

[ssrf]

project_root = "."              # used when level = project

[rate_limit]
requests_per_minute_per_domain = 60
per_domain_concurrency = 2
global_concurrency = 8

[robots]
respect = true
ignore_domains = []
default_ttl = "24h"

[cache]
default_ttl = "1h"
min_ttl = "5m"
max_ttl = "7d"
override_no_store = false
override_no_store_domains = []
store_raw_html = false

[headless]                      # only used when feature compiled in
auto_detect_spa = true
default_wait = "domcontentloaded"
timeout = "15s"
block_images = true
block_fonts = true
block_media = true
block_css = false
block_third_party = true

[backends.default]

[backends.openai]
```

`rover config show` prints the merged effective config (file + defaults). `rover config set <key> <value>` mutates the file safely (preserves comments via `toml_edit`).

## 15. Non-Functional Requirements

- **Binary size:** default build (no feature flags) under 25 MB
- **Cold start:** `rover fetch <simple_url>` completes in under 2 seconds for a well-cached page
- **Throughput:** handle 50 URLs in `batch_fetch` against a varied domain set in under 30 seconds at default concurrency
- **Memory:** baseline `rover mcp` resident memory under 100 MB without any feature flags
- **Cross-platform:** Linux x86_64 and aarch64, macOS Apple Silicon and Intel, Windows x86_64 (best-effort)
- **MSRV:** track stable Rust; no nightly dependencies
- **License:** MIT or Apache-2.0 dual license

## 16. Security Considerations

- **Prompt injection:** all fetched content is untrusted. Rover passes content through to the agent unchanged (this is correct behavior for a fetcher), but the implementation must never execute or interpret content. The agent is responsible for treating fetched text as data.
- **SSRF:** see §5.5; default `strict` level, opt-in to riskier modes
- **Cache poisoning:** cache key is `sha256(canonical_url)`; an attacker controlling DNS or routing could inject content for one canonical URL. Document this; consider checking content_hash against known-good values for high-value URLs as a future feature.
- **Path traversal in `file://` mode:** see §5.5; canonicalize after symlink resolution, verify project-root descendancy
- **Resource exhaustion:** enforce max page size (default 10 MB), max redirect chain (default 10), max headless render time (default 15s). Reject content above these limits with a clear error.
- **Secrets in URLs:** never log full URLs at info level if they contain query parameters that look secret-shaped (`api_key=`, `token=`, etc.). Provide a redaction pass.

## 19. Naming and Branding Notes

The project is named **Rover**. The binary is `rover`. The crate name on crates.io should be `rover-mcp` if `rover` is taken (likely is). Internal module organization should use `rover` as the crate name regardless.

User-facing strings should refer to "Rover" (capitalized). Log lines and error messages should be terse and actionable.
