# Automated Publishing (release-plz + cargo-dist) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace rover's hand-rolled release pipeline with release-plz (versioning, changelog, crates.io publish, tagging) + cargo-dist/`dist` (cross-platform binaries, GitHub Releases, shell installer, Homebrew), and rename the crate `rover-mcp` → `rover-fetch` so it can be published.

**Architecture:** Two-stage pipeline. On push to `main`, release-plz opens a Release PR; merging it publishes `rover-fetch` to crates.io and pushes a `vX.Y.Z` tag. That tag triggers dist's generated workflow, which builds the four target binaries (`--features headless`), creates the GitHub Release with a shell installer, and publishes the single `rover` Homebrew formula to `aaronbassett/homebrew-tap`. release-plz owns versioning + crates.io + the tag; dist owns binaries + the GitHub Release + Homebrew. `git_release_enable = false` keeps them from colliding.

**Tech Stack:** Rust (edition 2024, MSRV 1.96.0), GitHub Actions, `dist` 0.32.0 (installed locally), `release-plz` 0.3.158 CLI / `release-plz/action@v0.5`, Homebrew tap, crates.io.

## Global Constraints

These apply to every task. Exact values from the spec (`docs/superpowers/specs/2026-06-22-automated-publishing-design.md`):

- The installed **binary** and the importable **library** stay named `rover`. Only the crates.io **package** name changes: `rover-mcp` → `rover-fetch`.
- The crate's `[features] default = []` is **unchanged**. Only the *distributed* binary (prebuilt tarballs + Homebrew) is built `--features headless --no-default-features`, via dist config — never by changing the crate default.
- MSRV stays `rust-version = "1.96.0"`; `edition = "2024"`. Do not change them.
- Four targets, **no Windows**: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-apple-darwin`, `aarch64-apple-darwin`.
- dist is pinned: `cargo-dist-version = "0.32.0"`.
- First release is a clean **`v0.1.0`** (non-prerelease).
- Tag scheme is **`vX.Y.Z`** (so dist's trigger matches and the tag is unambiguous in a one-member workspace).
- Secrets already created on the repo (verified 2026-06-22): `CARGO_REGISTRY_TOKEN`, `RELEASE_PLZ_TOKEN` (a PAT/App token, **not** the default `GITHUB_TOKEN`), `HOMEBREW_TAP_TOKEN`. dist creates the GitHub Release with the auto-provided `GITHUB_TOKEN`.
- Commit messages use **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:`, …) — release-plz infers versions from them. The repo's lefthook `commit-msg` hook enforces this.
- **Never hand-edit** `.github/workflows/release.yml` — it is generated by `dist`. Regenerate with `dist generate`.
- Do **not** touch `ci.yml` or `smoketest.yml`.
- Do **not** rewrite historical records under `docs/superpowers/prd/` or `docs/superpowers/plans/` (the older milestone plans) — leaving their `rover-mcp` mentions intact is correct.

- [ ] **Step 3: Create `.github/workflows/release-plz.yml`**

```yaml
name: release-plz

on:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  # Publish any unpublished version to crates.io and push the `vX.Y.Z` tag.
  # The tag triggers dist's release.yml. release-plz does NOT create the GitHub
  # Release (git_release_enable = false) — dist owns that.
  release:
    name: release-plz release
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dtolnay/rust-toolchain@stable
      - name: Run release-plz release
        uses: release-plz/action@v0.5
        with:
          command: release
        env:
          # MUST be a PAT/App token, not the default GITHUB_TOKEN, or the pushed
          # tag will not trigger the dist release.yml workflow.
          GITHUB_TOKEN: ${{ secrets.RELEASE_PLZ_TOKEN }}
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}

  # Open/update the "Release PR" that bumps the version and updates the changelog.
  release-pr:
    name: release-plz release-pr
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
    concurrency:
      group: release-plz-${{ github.ref }}
      cancel-in-progress: false
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dtolnay/rust-toolchain@stable
      - name: Run release-plz release-pr
        uses: release-plz/action@v0.5
        with:
          command: release-pr
        env:
          GITHUB_TOKEN: ${{ secrets.RELEASE_PLZ_TOKEN }}
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}
```

````markdown
Rover's releases are automated by two tools:

- **[release-plz](https://release-plz.dev)** — versions, changelog, the crates.io

- **[dist](https://opensource.axo.dev/cargo-dist/)** (cargo-dist) — cross-platform

Three channels, all automated:

```
push to main ──► release-plz opens a "Release PR" (version bump + changelog)
     │
     ▼ merge the Release PR
release-plz: cargo publish rover-fetch ──► crates.io

## The distributed binary vs. `cargo install`

The prebuilt tarballs and the Homebrew formula ship `rover` built with
`--features headless --no-default-features`. The crate's own default feature set
is empty (`default = []`), so **`cargo install rover-fetch` builds the *basic*
binary**. To match the prebuilt binary from source:

```sh
cargo install rover-fetch --features headless
```

Other optional features (e.g. `local-inference`) work the same way.

| `CARGO_REGISTRY_TOKEN` | release-plz | `cargo publish` to crates.io |

## Cutting a release

Normal releases are hands-off:

1. Land changes on `main` using Conventional Commits (`feat:`, `fix:`, …).
2. release-plz opens/updates a **Release PR** that bumps the version and updates
   `CHANGELOG.md`. Review it.
3. **Merge the Release PR.** release-plz publishes to crates.io and pushes
   `vX.Y.Z`; the tag triggers dist, which builds the binaries, creates the GitHub
   Release, and updates the Homebrew tap.

A pre-release version (`X.Y.Z-rc.1`) is published to crates.io and GitHub but
**does not** update the Homebrew formula (dist skips prereleases).
````

## Notes for the implementer

- **`dist init` is interactive without `--yes`.** Always pass `--yes`; the config in `Cargo.toml` (Task 2 Step 1) is what it reads, so the output is deterministic.
- **If `dist plan` shows artifact names with a version** (e.g. `rover-0.1.0-<target>.tar.gz`) rather than `rover-<target>.tar.gz`, use whatever it prints in the README (Task 4 Steps 2). The plan assumes dist's default unversioned archive names.
- **If release-plz rejects `git_tag_name` under `[workspace]`**, move it into a `[[package]]` block keyed by `name = "rover-fetch"`. The `[workspace] git_release_enable = false` line is the load-bearing one and stays put.
- **Do not run `dist init` more than once per change** without re-checking `git diff Cargo.toml` — it rewrites/normalizes the config block.
